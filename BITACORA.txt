2. DECISIONES DE ARQUITECTURA Y DESPLIEGUE
--------------------------------------------------------------------------------

2.1 Monorepo, no multirepo
    Se mantiene un unico repositorio para backend, frontend y movil.
    Razon: microservicios exige independencia de despliegue y de base de datos,
    no de repositorio. Separar en 11 repos obligaria a publicar medcore-commons
    como artefacto versionado en un registry y a bumpear 11 poms por cada cambio,
    ademas de 14 pipelines y 14 juegos de secretos.

2.2 Sin repositorio medcore-config
    La guia pedia un repo privado aparte que el Config Server clonara en
    produccion. Se descarta.
    Razon: el Config Server corre siempre en modo native leyendo
    infra/config-repo/ desde disco. Esto elimina el token de GitHub, su
    expiracion, y un modo de falla el dia de la demostracion. Un solo repo.

2.3 Despliegue hibrido: backend local + frontend en Vercel
    Se evaluo Render para el backend y se descarto.
    Razon: el plan gratuito da 512 MB de RAM y 0.1 CPU por instancia, suspende
    tras 15 minutos sin trafico (lo que desregistra los servicios de Eureka), su
    Postgres gratuito expira a los 30 dias, y los Features on Demand de Kafka
    gratuitos ya no existen (Upstash Kafka discontinuado; Aiven free solo
    permite 5 topicos y el proyecto necesita 9).

    Modelo adoptado:
      [Navegador] --HTTPS--> [Vercel: medcore-frontend]
                                   |  VITE_API_BASE_URL
                                   v
                          [ngrok: dominio estatico]
                                   |
                                   v
                 [laptop: docker compose, solo :8080 expuesto]

    Ventajas: se recuperan Eureka y Config Server (la arquitectura completa de
    la guia queda demostrable), Kafka KRaft local con los 9 topicos, las 7 bases
    Postgres locales, sin limites de RAM ni arranques en frio.

    Reglas del despliegue:
      - Por el tunel se expone UNICAMENTE el 8080 del gateway.
        Nunca 8761, 5432, 27017 ni 9092.
      - El dominio de ngrok debe ser estatico y reservado: la URL se compila
        dentro del build de Vercel y dentro del APK.
      - En dominios gratuitos ngrok devuelve una pagina intersticial a los
        user-agent de navegador. El cliente HTTP debe enviar la cabecera
        ngrok-skip-browser-warning: true, o recibe HTML en vez de JSON.
      - CORS en el gateway con allowed-origins: ${FRONTEND_ORIGIN}.
      - JWT_SECRET de produccion con openssl rand -base64 64.

2.4 Versiones de Spring (verificadas en repo1.maven.org)
    Se descarto Spring Boot 4.1.1 pese a ser estable.
    Razon: ningun tren estable de Spring Cloud apunta a Boot 4.1.x.
      Spring Cloud 2025.1.4    -> spring-boot.version 4.0.9
      Spring Cloud 2026.0.0-RC1 -> spring-boot.version 4.2.0-RC1
    Como la arquitectura depende de Eureka, Config Server, Gateway y OpenFeign,
    manda el tren de Spring Cloud.

    Adoptado:  Spring Boot 4.0.9 + Spring Cloud 2025.1.4
      spring-cloud-netflix        5.0.3  (Eureka server y client)
      spring-cloud-config         5.0.6
      spring-cloud-gateway        5.0.4
      spring-cloud-openfeign      5.0.4
      spring-cloud-circuitbreaker 5.0.3

    IMPORTANTE: el starter del gateway se renombro en la rama 5.x.
      Correcto:   spring-cloud-starter-gateway-server-webflux
      Ya no existe: spring-cloud-starter-gateway

2.5 Sin CLAUDE.md
    Las convenciones del proyecto viven en README.md.

3.1 Instalacion de WSL2 y Docker - problema y solucion
    wsl --install dejaba WSL2 sin arrancar: "la virtualizacion no esta
    habilitada". La caracteristica VirtualMachinePlatform estaba en
    InstallState=2 y su payload NO estaba en WinSxS; se habia borrado meses
    antes al deshabilitar la caracteristica y limpiar residuos.

    Windows la trata como Feature on Demand
    (Windows.HyperV.OptionalFeature.VirtualMachinePlatform.Client.Disabled),
    por lo que NO esta dentro del install.wim de ninguna ISO normal: solo
    llega desde Windows Update o desde el FoD ISO de licenciamiento por volumen.

    Intentos que fallaron:
      - dism /enable-feature            -> bucle de descarga 50/100 <-> 0/100
      - optionalfeatures.exe            -> 0x800f0842 CBS_E_SESSION_FINALIZED
      - dism con /LimitAccess           -> 0x800f0912 (sin origen local)
      - dism con /Source:WIM desde ISO  -> 0x800f0912 (los FoD no van en el wim)
      - reset de SoftwareDistribution   -> 0x80072EE2 ERROR_INTERNET_TIMEOUT

    Diagnostico intermedio: sfc /scannow sin infracciones y
    dism /cleanup-image /restorehealth correcto, o sea que el sistema estaba
    sano; el problema era la entrega del payload.

    SOLUCION: instalar las actualizaciones pendientes de Windows Update. El
    equipo paso de build 26300.9711 a 26300.9818 y con esa build el payload si
    estaba disponible. VirtualMachinePlatform quedo en InstallState=1.

    Despues: wsl --install -d Ubuntu (WSL2, usuario kafu_usquiano) y
    winget install -e --id Docker.DockerDesktop (Docker Desktop 4.97.0).

    Verificado:
      Docker 29.9.2, Docker Compose v5.6.1, hello-world OK
      Motor con 8 CPUs y 15.62 GiB (limite fijado en C:\Users\kafuu\.wslconfig)

3.3 Servicios nativos que estorban  [PENDIENTE DE EJECUTAR]
    PostgreSQL 18 y MongoDB estan instalados como servicios de Windows en
    arranque automatico. Postgres nativo tiene tomado 0.0.0.0:5432 y mongod no

    no el contenedor. Se comprobo: el error de autenticacion llego en espanol,
    y el contenedor corre en ingles.

    Accion pendiente, en PowerShell como administrador:

      Set-Service MongoDB -StartupType Manual

5.1 Problemas resueltos
    Kafka salia con codigo 1: el volumen nombrado se crea como root pero el
    contenedor corre como uid=1000 (appuser), y no podia escribir meta.properties
    al formatear el directorio KRaft. Se quito el volumen; los topicos los
    recrea create-topics.sh, que es idempotente.

    docker exec desde Git Bash convertia /opt/kafka/... en
    C:/Program Files/Git/opt/kafka/... (traduccion de rutas de MSYS). El script
    ahora exporta MSYS_NO_PATHCONV=1 y MSYS2_ARG_CONV_EXCL="*".
